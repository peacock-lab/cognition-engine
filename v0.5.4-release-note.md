# v0.5.4 — Trusted Publishing Release Path

`v0.5.4` focuses on establishing the Trusted Publishing release path for Cognition Engine.

This release does not introduce major user-facing runtime features. Instead, it strengthens the release engineering baseline by publishing the project through PyPI Trusted Publishing, adding a minimal public GitHub Actions workflow for PyPI publishing, and keeping the existing project-token based release path as a fallback.

## What changed

1. Upgraded the root package and 10 subpackages to `0.5.4`.
2. Updated root package dependencies to `cognition-engine-*==0.5.4`.
3. Added a minimal public PyPI publish workflow for Trusted Publishing.
4. Configured Trusted Publisher entries for all 11 PyPI distributions.
5. Verified the post-release state through the release governance safety checks.
6. Kept the Keychain project-token fallback path for emergency rollback use.

## Verification

The post-release verification confirmed:

- all 11 PyPI distributions exist at `0.5.4`;
- installation verification passed;
- package metadata verification passed;
- public repository version and tag checks passed;
- `v0.5.4` tag exists in the public repository.

## Known note

The first Trusted Publishing workflow run uploaded the packages successfully, but the GitHub Actions `postverify` job failed because it still checked the legacy import path:

```bash
python -c "import cognition_engine"
```

The root package is now an aggregate package and no longer publishes the legacy `cognition_engine` module. The PyPI publication itself succeeded, and local post-release verification passed. A future workflow update should align the `postverify` step with the current multi-package aggregate structure.

## Scope

`v0.5.4` is a release engineering milestone. It focuses on Trusted Publishing and controlled release verification, while keeping the public package structure aligned with the modular `packages/` layout.
